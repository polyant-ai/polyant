# Polyant v1.3.4

Polyant v1.3.4 brings the Monitor, one timeline of what the agents of a
workspace did, and adds a few controls that were missing: a switch on each
knowledge document, an editable skill name and description, and a Message
details sheet that shows what a turn sent to the model and what it cost. The
rest is panel polish, fixes, internal simplification and dependency updates.
It needs no configuration change; its one migration runs on its own at
start-up.

## Highlights

- **The Monitor.** One timeline per workspace lists tool calls, hook
  executions, webhook-started conversations and scheduled task runs, with live
  updates, filters and a detail drawer. It replaces the Activity page and the
  tool-call list, whose old addresses open it, and the agent's Logs tab, now
  called Monitor, shows the same view for that agent. The engine serves it at
  `GET /api/monitor` and `GET /api/monitor/:type/:id`; a type the caller may not
  read is left out of the list rather than refusing the whole request.
- **Knowledge documents can be switched off.** A document that is off stays
  stored and listed, and retrieval skips it until it is switched on again
  (`PATCH /api/instances/:slug/knowledge/:docId` with `{ "enabled": boolean }`).
- **Editable skill name and description.** `PUT /api/skills/:name` accepts
  `displayName`; the slug stays fixed, so agents keep finding the skill.
- **Model calls from tools.** A tool asks a model with `ctx.ai.chat` and a
  tier, and the engine runs the call through its AI gateway on the agent's
  provider, logged and priced like the turn's own calls. `ctx.abortSignal` stops
  it when nobody waits for the result. Plugins get both from
  `@polyant-ai/plugin-sdk` 1.11.0.
- **Message details.** The Debug sheet becomes "Message details", in tabs, with
  a Copy action on the prompt, the messages and the conversation state, and a
  table of the turn's model calls with their duration, tokens, cost and outcome.
- **Web/API channel.** The channel tab shows the endpoint to call, the
  authentication header, and server-side curl and fetch examples.
- **Panel.** The conversation list shows and filters by contact, the agent
  header fits on one line, the user menu moves to the header, and the Italian
  copy has been reviewed.

## Breaking changes

None. The additions to the HTTP API are optional fields and new routes. The
missing-permission 403 keeps its message and adds `code` and `permission`.

## Security

- MCP server secrets of 8 characters or fewer are fully masked in API
  responses instead of showing their last four characters.
- markdown-it 15.0.3 and Vite 8.3.5 for their published security fixes.

## Upgrading

No new configuration variable. Migration `0096` adds
`knowledge_documents.enabled`, `true` for every existing document.

1. Run `npm ci`.
2. Run `npm run build`.
3. Restart the services.
