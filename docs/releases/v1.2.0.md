# Polyant v1.2.0

Polyant v1.2.0 moves product behaviour to the scope that owns it: installation
policies are editable by platform admins, agent behaviour is configurable per
agent, and attachment storage uses each agent's bucket. It makes the core
runtime leaner by moving integration-heavy tool families into build-time
plugins, receives Telegram and Slack through webhooks, and runs on Node 24.
That cleanup is deliberately breaking: Google sign-in and the environment
variables that set product behaviour are gone, extracted tools need their
plugins installed and take namespaced names, storing inbound attachments
becomes a per-agent opt-in, and custom S3 endpoints are not supported.

> **Read [docs/UPGRADING.md](../UPGRADING.md) before starting.** Accounts that
> only used Google need passwords, extracted tools need their plugins,
> MinIO/R2 users need to move attachment storage to AWS S3, agents that should
> keep users' files need **Store attachments** turned on, Telegram and Slack
> need a public address, and non-default values of the removed variables have
> to be entered in the panel.

## Highlights

- **Settings live at the right tier.** Settings → General holds the
  installation's operational policies: analytics retention, the engine's public
  address, live-stream caps, rate limits, agent-to-agent and MCP timeouts, and
  scheduler deadlines. Each agent can set its timezone, locale, memory
  deduplication and message timing, and knowledge-document caps can vary by
  organization. The shipped defaults are unchanged.
- **A smaller core, with build-time plugins.** GitHub, Render, HubSpot and
  Markdown-to-PDF tools moved to plugins, so the base image no longer carries
  their optional binaries and libraries. A plugin can declare its Alpine, global
  npm and environment requirements, and the Docker build installs their union.
  Manifests can also name the plugin and describe the parameters its tools ask
  for, and the panel shows them.
- **Telegram and Slack through webhooks.** Both channels now arrive like
  WhatsApp, on `/webhooks/*`, and the Telegram webhook survives rolling
  deploys. A failed Telegram registration is retried instead of disabling the
  channel, redelivered updates and events are dropped, and each bot's webhooks
  are rate limited on their own. The CDK stack routes webhook and HTTP-channel
  traffic to the engine without the panel's sign-in.
- **Web chat context.** `chat/stream` and `/v1/chat/completions` accept a
  `context` object projected onto the conversation state through a per-agent
  field mapping, so a web or voice front end can hand tools and hooks the
  caller's identity. An agent that maps a context field requires its key on
  every web turn. On both routes, a client that disconnects before the turn
  produced anything aborts it, and a turn that has produced output runs to its
  end and is saved.
- **A clearer agent page.** Tools and hooks open in side sheets with the
  parameters they declare, conversations can be followed live on any channel,
  activity reads as a timeline and now includes tool calls, and the page says
  what a capability still needs before it works.
- **Updated models and gateway.** OpenAI gpt-6, Claude Opus 5, Opus 5.5,
  Sonnet 5.5 and Fable 5.1, and new Nebius models are in the catalog, with
  corrected prices. Providers and embedders can be registered at boot, and
  switching thinking off now really switches it off.
- **Bedrock works without Anthropic approval.** The default standard tier uses
  Amazon Nova Pro and the heavy tier uses OpenAI gpt-oss 120B. Nova retains
  system-prompt caching while avoiding unsupported cache markers on tool
  messages.
- **One bucket per agent, and attachments kept only by choice.** Attachment
  persistence and `fileUpload` now share the same per-agent S3 configuration,
  including an explicit ECS task-role option. Each agent decides whether to
  keep the files its users send, and stored files are deleted with their
  conversation and with the agent. Filenames with URL-significant characters
  round-trip correctly.
- **Scheduled work recovers.** Runs left behind by a dead process are recovered
  at startup; live runs that exceed their configured deadline are reaped
  without touching a newer claim of the same task, and a scheduler health
  endpoint exposes stuck-run and capacity counts.
- **Faster and cleaner on Node 24.** Under load the platform's overhead per
  turn drops sharply on Node 24, and the engine now finishes shutting down
  while a panel holds an activity stream open, instead of waiting for the
  platform to kill it and losing the last buffered audit rows.
- **Faster lists and dashboards.** Conversations carry their own message
  counters, so lists and analytics no longer count message history, and
  analytics reads run on a separate, smaller connection pool.

## Breaking changes

- The engine and the panel require Node 24. The published images carry it;
  source deployments and custom images must move.
- Extracted tools are namespaced. Migration `0087_rename_extracted_tools`
  renames their rows in place, so agents keep them enabled and skills keep
  their links; install the relevant plugins before building. `verifyDocument`
  has no replacement and is removed from agents at the first boot.
- Telegram and Slack need a public HTTPS address with `/webhooks/*` routed to
  the engine. Each Slack app needs Socket Mode off and its Request URL set to
  the agent's webhook; the Slack app token is no longer used.
- Google sign-in is removed. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
  `AUTH_ALLOWED_DOMAIN` and `AUTH_ALLOWED_DOMAINS` are gone; ensure every user
  has a password before upgrading.
- `AUTH_MODE`, `DEFAULT_INSTANCE_ID`, deployment-wide `AWS_REGION`,
  `PLATFORM_ADMIN_EMAIL`, `WORKSPACES_ROOT`, `DEBUG_LLM_PAYLOAD` and the unused
  `LANGSMITH_*` variables are no longer product configuration.
- The environment variables that set agent, organization or installation
  behaviour are read by nothing; the panel holds those values now. Their
  defaults are unchanged, and a deployment that set a different value must enter
  it in the panel before removing the variable. `THROTTLE_ENABLED` stays an
  environment variable.
- Attachment storage no longer reads the four `PLATFORM_S3_*` variables. Set
  `s3_bucket_name`, `aws_region` and either static credentials or
  `s3_use_task_role` on each agent that needs persisted attachments, and turn
  on its **Store attachments** switch: migration `0088` adds it off for every
  agent. Deleting stored files needs `s3:DeleteObject` on the `attachments/`
  prefix. Files earlier versions stored in the platform bucket stay there.
- `s3_endpoint` is removed and migration `0081_drop_s3_endpoint_secret` deletes
  stored values. Version 1.2.0 has no supported MinIO, Cloudflare R2 or other
  custom-endpoint path.
- Unpinned OpenAI agents move from `gpt-4o-mini`/`gpt-4o` to the gpt-6 tiers,
  and unpinned Bedrock agents to Nova Pro and gpt-oss 120B.

## Security

- Plugin artifacts are limited to 10 MB each, 10 minutes of lifetime, and
  100 MB or 1,000 live handles per engine process.
- The removed `s3_endpoint` was an SSRF primitive: an agent secret could direct
  attachment contents to an arbitrary host. Storage now uses AWS endpoints with
  each agent's own bucket and credential configuration.
- Tenant scope is required and branded across the affected stores, closing
  cross-tenant keyword search and mutation paths and refusing unresolved request
  tenancy rather than dropping a predicate.
- Disabled skills no longer resolve retained credential placeholders. MCP OAuth
  metadata uses the shared private-network denylist, rotating bearer strings no
  longer evade throttling indefinitely, and provider response bodies are not
  logged raw.
- undici was updated to 8.11.2 and 7.30.0 for its open security advisories.

## Upgrading

1. Back up PostgreSQL; migration `0081` deletes stored `s3_endpoint` values,
   and migration `0086` reads every conversation message, so schedule it for a
   quiet moment or build its indexes beforehand as the upgrade guide shows.
2. Move to Node 24 if you run from source or build your own images.
3. Give every Google-only account a password before replacing the old web app.
4. Add the plugins of the extracted tools your agents use to the image.
5. Move any MinIO/R2 attachment bucket to AWS S3, configure storage on each
   agent and turn on **Store attachments** where files should be kept. Copy any non-default value of a removed variable into the panel, then
   remove the obsolete environment variables listed in the upgrade guide.
6. Route `/webhooks/*` to the engine and reconfigure Slack apps for webhooks.
7. Run `npm ci`, apply migrations, build, restart, then smoke-test sign-in, one
   affected plugin tool, attachment upload/read, a Telegram or Slack message if
   you use them, and a scheduled task.
