# Polyant v1.2.0

Polyant v1.2.0 moves product behaviour to the scope that owns it: platform
policies are editable by platform admins, agent behaviour is configurable per
agent, and attachment storage uses each agent's bucket. It also makes the core
runtime substantially leaner by moving integration-heavy tool families into
build-time plugins. That cleanup is deliberately breaking: Google sign-in and
several deployment-wide configuration aliases are gone, extracted tools need to
be installed and re-enabled under namespaced names, and custom S3 endpoints are
not supported.

> **Read [docs/UPGRADING.md](../UPGRADING.md) before starting.** Accounts that
> only used Google need passwords, extracted tools need plugins and new enabled
> rows, and MinIO/R2 users need to move attachment storage to AWS S3.

## Highlights

- **Settings live at the right tier.** Platform admins can set analytics
  retention and per-user SSE limits in Settings → General. Each agent can
  override timezone, locale, memory deduplication and message timing, while the
  existing environment values remain defaults. Knowledge-document caps can vary
  by organization.
- **A smaller core, with build-time plugins.** GitHub, Render, HubSpot and
  Markdown-to-PDF tools moved to plugins, so the base image no longer carries
  their optional binaries and libraries. A plugin can declare its Alpine, global
  npm and environment requirements, and the Docker build installs their union.
- **One bucket per agent.** Attachment persistence and `fileUpload` now share
  the same per-agent S3 configuration, including an explicit ECS task-role
  option. Filenames with URL-significant characters round-trip correctly.
- **Scheduled work recovers.** Runs left behind by a dead process are recovered
  at startup; live runs that exceed their configured deadline are reaped, and a
  scheduler health endpoint exposes stuck-run and capacity counts.
- **Bedrock works without Anthropic approval.** The default standard tier uses
  Amazon Nova Pro and the heavy tier uses OpenAI gpt-oss 120B. Nova retains
  system-prompt caching while avoiding unsupported cache markers on tool
  messages.
- **Debug turns are portable.** The Debug sheet copies the captured prompt,
  messages, tools and step trace as one JSON object, including a steps-only form
  when payload capture was disabled.

## Breaking changes

- Extracted tools are namespaced and represented by new registry rows. Install
  the relevant plugins, update skill references, and re-enable the replacements
  on every affected agent. `verifyDocument` has no replacement.
- Google sign-in is removed. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
  `AUTH_ALLOWED_DOMAIN` and `AUTH_ALLOWED_DOMAINS` are gone; ensure every user
  has a password before upgrading.
- `AUTH_MODE`, `DEFAULT_INSTANCE_ID`, deployment-wide `AWS_REGION`,
  `PLATFORM_ADMIN_EMAIL`, `WORKSPACES_ROOT`, `DEBUG_LLM_PAYLOAD` and the unused
  `LANGSMITH_*` variables are no longer product configuration.
- Attachment storage no longer reads the four `PLATFORM_S3_*` variables. Set
  `s3_bucket_name`, `aws_region` and either static credentials or
  `s3_use_task_role` on each agent that needs persisted attachments.
- `s3_endpoint` is removed and migration `0081_drop_s3_endpoint_secret` deletes
  stored values. Version 1.2.0 has no supported MinIO, Cloudflare R2 or other
  custom-endpoint path.

## Security

- The removed `s3_endpoint` was an SSRF primitive: an agent secret could direct
  attachment contents to an arbitrary host. Storage now uses AWS endpoints with
  each agent's own bucket and credential configuration.
- Tenant scope is required and branded across the affected stores, closing
  cross-tenant keyword search and mutation paths and refusing unresolved request
  tenancy rather than dropping a predicate.
- Disabled skills no longer resolve retained credential placeholders. MCP OAuth
  metadata uses the shared private-network denylist, rotating bearer strings no
  longer evade throttling indefinitely, and provider response bodies are not
  logged raw.
- Next.js, Sharp, js-yaml, Multer and qs were updated for applicable security
  advisories.

## Upgrading

1. Back up PostgreSQL; migration `0081` deletes stored `s3_endpoint` values.
2. Give every Google-only account a password before replacing the old web app.
3. Add required tool plugins to the image, update old tool-name references, and
   re-enable their namespaced replacements after the new engine starts.
4. Move any MinIO/R2 attachment bucket to AWS S3 and configure storage on each
   agent. Remove obsolete environment variables listed in the upgrade guide.
5. Run `npm ci`, apply migrations, build, restart, then smoke-test sign-in, one
   affected plugin tool, attachment upload/read and a scheduled task.
