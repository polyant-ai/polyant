# Polyant v1.3.0

Polyant v1.3.0 lets an MCP server act as one shared account for a whole agent,
and lets plugins speak the reader's language: a manifest's name and
description, and each tool's summary and field labels, can be written once per
language. It needs no configuration change, and its two migrations run on their
own at start-up.

## Highlights

- **One shared account for an OAuth MCP server.** An admin connects the account
  once from the agent's MCP section and every conversation uses it through a
  pooled connection. Until it is connected the server offers nothing, not a
  connect link, because nobody in a conversation may authorize the agent's
  account. Authorizing in each conversation stays available and is the default.
- **Localized plugin text.** `displayName` and `description` in a plugin
  manifest accept one text per BCP 47 tag besides a plain string. The engine
  serves the map as written; the panel picks the reader's tag, then the same
  language, then English, then the first tag.
- **Tool summaries and field labels for people.** A tool or hook can carry a
  `summary`, and its configuration fields a `label` and `description`, one text
  per locale (plugin SDK 1.10.0). The Tools section, the tool picker and the hook
  panels show them; the description the model reads stays one string, shown in
  the tool's panel as the text the agent reads. Every built-in tool and hook has
  them in English and Italian, and the panel names tool categories in both.
- **Panel.** About is the last item of the Help menu, the agent page section
  "To review" is now "Alerts", and the chip switchers share one component.

## Upgrading

No operator action. Migration `0094` adds the shared-account columns to the
MCP servers table and `0095` gives `instance_hooks.action_type` the database
default the schema already declared.

A plugin whose manifest uses a locale map declares `"engine": ">=1.3.0"`; an
older engine skips it at load time.

## Security

- Shared-account tokens are encrypted at rest, kept out of the configuration
  the panel reads back and out of the agent export, and dropped when the server
  moves to another address or stops using the shared account. Connecting and
  disconnecting are audited.
- A refused refresh of a shared account clears the stored tokens only while
  they are still the ones that refresh used, so two refreshes racing on
  different nodes cannot disconnect the agent.
