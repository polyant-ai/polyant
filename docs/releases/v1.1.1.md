# Polyant v1.1.1

Polyant v1.1.1 is a patch release with a single purpose: on 1.1.0 no agent can be
created, on any installation, and this restores it. Anyone running 1.1.0 should
upgrade; anyone installing Polyant for the first time should start here rather
than at 1.1.0.

## Highlights

- **Creating an agent works again.** In 1.1.0 `POST /api/instances` answered 500 on
  every call, and with it the "New Agent" button in the admin panel, so a fresh
  installation could not get past the quick start. 1.1.0 moved the create path into
  a single transaction so a crash could no longer commit a half-configured agent,
  but the tool seed kept issuing its insert on the shared connection pool rather
  than on that transaction. A second connection cannot see the agent row the first
  one has not committed, so the insert failed the foreign key
  `instance_tools_instance_id_fkey` and the whole request rolled back. Every read
  and write on the create path now runs on the caller's transaction, and the
  atomicity 1.1.0 introduced is kept.

- **The create path is now covered against a real database.** The defect passed a
  full green suite because the unit tests mock the database: they can check which
  arguments a seed helper receives, never which connection its writes take. A new
  integration test creates an agent against PostgreSQL and asserts it ends up with
  its tools and prompt sections. Run against the 1.1.0 sources it reproduces the
  production error exactly.

## Breaking changes

None.

## Security

No security fixes in this release.

## Upgrading

No database migration and no new configuration variable. Existing agents and their
configuration are untouched.

1. Back up PostgreSQL.
2. Run `npm ci`.
3. Run `npm run build`.
4. Restart the services, then create an agent from the admin panel as a smoke test.

## Compatibility

Semantic Versioning applies to the documented OpenAI-compatible API, Plugin SDK and
manifest, and documented configuration and migration behavior. Internal engine
modules and the admin UI are not public SemVer surfaces.

This release changes no request or response shape. `recomputeInstanceTools` takes an
optional executor argument, an internal engine module with no public surface.
